## The three things that mattered

### 1. `wealthos-api` is not the service. `wealthos` is.

Two systemd units existed, both titled "WealthOS API", both with an identical
`ExecStart` on port 8000:

| Unit | Created | Reality |
|---|---|---|
| `wealthos.service` | 2026-05-27 **20:17** | holds the port, serves everything |
| `wealthos-api.service` | 2026-05-27 **07:30** | cannot bind, crash-loops |

`WEALTHOS_FULL_STATE_2026_05_27.md` stated the opposite as a **CRITICAL**
instruction. It was correct the morning it was written; `wealthos.service` was
created that evening, took the port, and no doc was ever updated.

**Every `systemctl restart wealthos-api` since has been a silent no-op** — it
returns success while the real process keeps running May code with stale
environment. That is why a placeholder `ANTHROPIC_API_KEY` survived weeks of
"fixes", and why deploys appeared not to land for ten weeks.

`wealthos-api` is now **disabled**. The correction is in `CLAUDE.md` §12 (always
in context), `WEALTHOS_FULL_STATE_2026_05_27.md` §2, and every handoff doc.

I got this wrong in my own first report too — the PIDs were adjacent (1928127 vs
1928129) and both units showed "active", so I conflated them. Corrected in
`docs/PHASE1_STATUS.md`.

### 2. All fund constituents are modelled, and the system presented them as real

All 381 `fund_constituents` rows came from `generate_synthetic_portfolio()` — a
hardcoded SEBI-mandate template — written in a **3-second window** on
2026-05-27. HDFC Silver ETF FoF was reported holding HDFC Bank 8%, ICICI 6.5%,
Reliance 6%.

The root cause was provenance loss: `get_fund_constituents()` returned
`"synthetic_estimated"` on first generation, but `store_constituents()` dropped
the tag and every later read returned `"cache"`. Modelled data was laundered
into apparent fact from the second call onward.

Phase 1 fixed **disclosure, not removal** — `generate_synthetic_portfolio()`
remains as a labelled fallback.

### 3. Fixing the API key made the system more convincing without making it more correct

Before: AI Memo returned 500. After: 16,000 characters of fluent, confident,
advisor-grade prose — a chunk of it narrating fund holdings that do not exist,
in the same authoritative voice, with no visual distinction.

This is why the disclosure work had to land before, not after.

## Phase A — AMFI crawler investigation

Full detail: [`AMFI_LAYOUTS.md`](AMFI_LAYOUTS.md). Spec:
[`AMFI_CRAWLER_SPEC.md`](AMFI_CRAWLER_SPEC.md). Fixtures:
`backend/tests/fixtures/amfi/`.

**The brief's premise was wrong.** AMFI does not aggregate workbooks — its
disclosure page is a Next.js directory of **links to 51 AMCs' own websites**.
This is 10 site-specific crawlers, not one.

**The geo-restriction belief was also wrong.** The box is in Bangalore
(DigitalOcean, `country: IN`) and AMFI returns 200. That assumption misdirected
this work for months.

**Acquisition:** 4 of 10 obtainable (Nippon via curl; SBI, Mirae, DSP via
headless browser). HDFC 403s even a real browser — recorded blocked, left alone.
ICICI's link in AMFI's own directory **404s**. Kotak/ABSL/UTI/Axis trigger
downloads by script with no href.

**AMFI hosts no copy of anything.** If an AMC blocks us there is no second source.

**The finding that matters most** — same regulator, same month:

| AMC | Header | Sum over ISIN rows | Convention |
|---|---|---|---|
| Nippon | `% to NAV` | 0.9869 | fraction |
| Mirae | `% to Net Assets` | 0.9863 | fraction |
| SBI | `% to AUM` | 96.17 | **percentage** |

Two incompatible conventions, none declared. A generic parser is silently 100×
wrong on one of them. Gate G1 catches it — the validation gates are load-bearing.

**My own spec had a bug Phase A caught:** G2's ISIN regex `^INE[0-9A-Z]{9}$`
rejects **26.4% of real ISINs** (490 of 1,856) — every government security, SDL,
T-bill and MF unit. It would have rejected every debt scheme. Corrected to
`^IN[A-Z0-9]{10}$`.

### Answers to the two blocking questions

1. **Archives ARE retrievable** — Nippon 2013→, SBI 2023→, DSP 2013→. History
   does not only accrue forward. **Exception: Mirae exposed only the current
   month**, so start collecting Mirae now or those months may be unrecoverable.
2. **Playwright costs ~716 MB and is unsafe on this box as configured** — 1.97 GB
   RAM, 1.19 GB available, **no swap**, 1 vCPU, API at 186 MB. Chromium peaks
   300–700 MB/page; with no swap the OOM killer can take `wealthos.service`
   instead of the browser, so a crawler bug becomes an API outage.
   **Add 2–4 GB swap before any browser-dependent adapter runs there.**
